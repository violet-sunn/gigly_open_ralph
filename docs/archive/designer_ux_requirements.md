# Требования к UX/UI для платформы Gigly

**Дата:** 2026-02-22
**Версия:** 1.0
**Назначение:** Руководство для команды дизайна

---

## Обзор платформы

### Что такое Gigly?

Gigly — это платформа, которая соединяет заказчиков с IT-специалистами для выполнения технических заданий. Платформа обеспечивает полный цикл работы: от публикации задания до его оплаты.

### Роли пользователей

Платформа поддерживает три типа пользователей:

**Клиент** — заказчик, который:
- Публикует задания
- Просматривает заявки от специалистов
- Выбирает исполнителя
- Принимает выполненную работу
- Оплачивает работу

**Специалист** — исполнитель, который:
- Просматривает доступные задания
- Подаёт заявки на интересующие задания
- Выполняет работу
- Сдаёт результат на проверку

**Администратор** — модератор, который:
- Управляет пользователями
- Модерирует задания
- Блокирует нарушителей

### Основные разделы платформы

1. **Публичные страницы** — доступны всем посетителям
   - Главная страница
   - Регистрация
   - Вход в систему

2. **Личный кабинет** — доступен после входа
   - Дашборд (главная страница после входа)
   - Профиль пользователя
   - Задания
   - Сообщения

3. **Панель администратора** — доступна только администраторам
   - Управление пользователями
   - Модерация заданий

## Экраны регистрации и входа

### Экран регистрации

**Назначение:** Создание нового аккаунта на платформе

**Кто видит:** Неавторизованные посетители

**Отображаемые элементы:**
- Заголовок: "Создайте свой аккаунт"
- Подзаголовок: "Зарегистрируйтесь, чтобы начать работу с Gigly"
- Форма регистрации
- Ссылка "Уже есть аккаунт? Войти"

**Поля формы для дизайна:**

1. **Выбор роли** (обязательное)
   - Тип: Радио-кнопки (две опции)
   - Варианты:
     - "Клиент" — Публикую задания, нанимаю специалистов
     - "Специалист" — Ищу задания, выполняю работу
   - Визуально: Карточки с описанием, одна из которых выбрана

2. **Email** (обязательное)
   - Тип: Текстовое поле
   - Формат: Email-адрес
   - Плейсхолдер: "you@example.com"

3. **Пароль** (обязательное)
   - Тип: Поле для пароля (скрытый текст)
   - Плейсхолдер: "••••••••"
   - Требования к паролю:
     - Минимум 8 символов
     - Максимум 72 символа
     - Должен содержать хотя бы одну заглавную букву
     - Должен содержать хотя бы одну строчную букву
     - Должен содержать хотя бы одну цифру
     - Только латинские буквы, цифры и спецсимволы

**Доступные кнопки:**
- "Зарегистрироваться" (основная кнопка)
  - Состояния: обычное, загрузка ("Регистрация...")
  - При успехе: переход на дашборд

**Сообщения об ошибках:**
- "Аккаунт с таким email уже существует"
- "Пароль должен быть не менее 8 символов"
- "Пароль должен содержать заглавную букву"
- "Пароль должен содержать строчную букву"
- "Пароль должен содержать цифру"
- "Пароль может содержать только латинские буквы, цифры и спецсимволы"
- "Выберите роль"
- "Слишком много попыток регистрации. Попробуйте через X минут"

## Экраны клиента

### Экран создания задания

**Назначение:** Публикация нового задания для специалистов

**Кто видит:** Только клиенты

**Отображаемые элементы:**
- Заголовок: "Опубликовать задание"
- Подзаголовок: "Опишите работу и установите бюджет"
- Форма создания задания (разделена на секции)

**Секция 1: Базовая информация**

1. **Название** (обязательное)
   - Тип: Текстовое поле
   - Плейсхолдер: "например, Создать React-дашборд"

2. **Описание** (обязательное)
   - Тип: Текстовая область
   - Строк: 4
   - Плейсхолдер: "Подробно опишите объём работы..."

**Секция 2: Требования и критерии успеха**

Заголовок секции: "Требования и критерии успеха"
Ссылка: "💡 Посмотреть примеры заданий для вдохновения" (открывает в новой вкладке)

3. **Критерии приёмки (Definition of Done)** (обязательное)
   - Тип: Текстовая область
   - Строк: 5
   - Минимум: 50 символов
   - Плейсхолдер: "Что означает 'готово'? Будьте конкретны: результаты, стандарты качества, метрики успеха. Пример: 'API возвращает данные пользователя в формате JSON с временем отклика <200мс, включает unit-тесты с покрытием >80%, развёрнуто в staging-окружении.'"
   - Счётчик символов: показывает текущее количество / минимум 50
   - Предупреждение: если меньше 50 символов, показать подсказку о качестве

4. **Цель / Желаемый результат** (необязательное)
   - Тип: Текстовая область
   - Строк: 3
   - Максимум: 1000 символов
   - Плейсхолдер: "Пример: Нам нужно мигрировать аутентификацию пользователей с кастомного решения на OAuth 2.0 для улучшения безопасности и снижения нагрузки на поддержку."
   - Пояснение: "Опционально: Опишите бизнес- или техническую проблему, которую вы решаете. Как выглядит успех?"
   - Счётчик символов: показывает текущее количество / максимум 1000

5. **Конкретные результаты** (необязательное)
   - Тип: Текстовая область
   - Строк: 3
   - Максимум: 1000 символов
   - Плейсхолдер: "Пример: 1. Интеграция OAuth 2.0 с Google и GitHub\n2. Скрипт миграции для существующих пользователей\n3. Обновлённая документация\n4. Развёртывание в staging и production"
   - Пояснение: "Опционально: Перечислите конкретные выходные данные, которые вы ожидаете (функции, документация, развёртывания и т.д.)"
   - Счётчик символов

6. **Ограничения и предпочтения** (необязательное)
   - Тип: Текстовая область
   - Строк: 3
   - Максимум: 1000 символов
   - Плейсхолдер: "Пример: Должна сохраняться обратная совместимость с существующими API-эндпоинтами. Предпочтительно использование библиотеки Passport.js. Дедлайн: конец Q1 2026."
   - Пояснение: "Опционально: Технические предпочтения, временные рамки, требования совместимости или другие ограничения."
   - Счётчик символов

**Секция 3: Бюджет и детали**

7. **Бюджет (₽)** (обязательное)
   - Тип: Числовое поле
   - Минимум: 1
   - Шаг: 1
   - Плейсхолдер: "100000"

**Предпросмотр бюджета** (показывается при заполнении):
- Бюджет: 100 000 ₽
- Комиссия сервиса (10%): 10 000 ₽
- Итого: 110 000 ₽

8. **Теги** (необязательное)
   - Тип: Текстовое поле
   - Плейсхолдер: "React, TypeScript, Node.js"
   - Пояснение: "Опционально, через запятую"

**Доступные кнопки:**
- "Опубликовать задание" (основная кнопка)
  - Состояния: обычное, загрузка ("Публикация...")
  - При успехе: переход на дашборд

**Сообщения об ошибках:**
- "Название, описание и критерии приёмки обязательны"
- "Критерии приёмки должны содержать минимум 50 символов"
- "Бюджет должен быть положительным числом"

### Экран просмотра задания и заявок

**Назначение:** Просмотр деталей задания и управление заявками от специалистов

**Кто видит:**
- Клиент (владелец задания) — видит все заявки и может управлять ими
- Специалист — видит детали задания и может подать заявку
- Все авторизованные пользователи — могут просматривать детали задания

**Отображаемая информация о задании:**

- Название задания
- Статус задания (бейдж):
  - "OPEN" — синий
  - "IN_PROGRESS" — синий
  - "REVIEW" — синий
  - "Completed - Awaiting Payment" — жёлтый
  - "Paid" — зелёный
- Описание задания
- Дополнительные требования (если заполнены):
  - 🎯 Цель / Желаемый результат
  - 📦 Конкретные результаты
  - ⚙️ Ограничения и предпочтения
- Критерии приёмки (выделенная секция с синей границей слева)
- Бюджет (в рублях)
- Автор задания (email и название компании, если заполнено)
- Теги (список бейджей)
- Дата публикации

**Специальные индикаторы:**

Если задание — пример:
- Бейдж "✨ Example"
- Информационный блок: "Это пример задания, демонстрирующий лучшие практики написания чётких требований. Используйте его как референс при создании своих заданий."

Если задание оплачено:
- Зелёный блок: "Оплата подтверждена: [дата]"

Если задание закрыто администратором:
- Красный блок: "Это задание закрыто администраторами и больше не принимает заявки. Закрыто: [дата]"

---

**Секция заявок (видит только владелец задания):**

Заголовок: "Заявки ([количество])"

Если заявок нет:
- Текст: "Заявок пока нет"

Для каждой заявки отображается:

**Информация о специалисте:**
- Имя специалиста (ссылка на профиль)
- Email в скобках
- Бейдж уровня опыта (если указан): "MIDDLE" или "SENIOR" (фиолетовый)
- Список технологий (бейджи, если указаны)

**Содержание заявки:**
- 🔧 Технический подход (текст заявки)
- ❓ Уточняющие вопросы (текст заявки)
- ⏱️ Оценка трудозатрат (если указана, серым цветом)

**Статус заявки (бейдж):**
- "Pending" — жёлтый
- "Accepted" — зелёный
- "Rejected" — красный

**Дата подачи заявки**

**Кнопки действий** (только для заявок со статусом "Pending" и если задание в статусе "OPEN"):
- "Принять" (зелёная кнопка)
- "Отклонить" (красная кнопка)

**Что происходит при принятии заявки:**
- Статус задания меняется на "IN_PROGRESS"
- Специалист назначается на задание
- Все остальные заявки автоматически отклоняются
- Становится доступен обмен сообщениями

### Экран проверки выполненной работы

**Назначение:** Проверка и приёмка работы, сданной специалистом

**Кто видит:** Только владелец задания, когда статус задания "REVIEW"

**Отображаемые элементы:**
- Заголовок секции: "Проверить сданную работу"
- Информационный блок (голубой): "Сдал: [email специалиста]"
- Пояснительный текст: "Проверьте работу специалиста и одобрите её, чтобы отметить задание как выполненное"

**Доступные кнопки:**
- "Одобрить работу" (зелёная кнопка)
  - При нажатии: статус задания меняется на "COMPLETED"

---

### Экран отметки об оплате

**Назначение:** Подтверждение оплаты выполненной работы

**Кто видит:** Только владелец задания, когда статус задания "COMPLETED"

**Отображаемые элементы:**
- Заголовок секции: "Отметить как оплачено"
- Пояснительный текст: "После того, как вы оплатили специалисту, отметьте это задание как оплаченное для завершения транзакции"

**Доступные кнопки:**
- "Отметить как оплачено" (зелёная кнопка)
  - При нажатии: статус задания меняется на "PAID", сохраняется дата оплаты

---

### Жизненный цикл задания (для понимания дизайнерами)

Задание проходит через следующие этапы:

1. **OPEN** (Открыто)
   - Задание опубликовано
   - Специалисты могут подавать заявки
   - Клиент может принимать или отклонять заявки

2. **IN_PROGRESS** (В работе)
   - Специалист назначен
   - Специалист выполняет работу
   - Доступен обмен сообщениями
   - Специалист может сдать работу

3. **REVIEW** (На проверке)
   - Специалист сдал работу
   - Клиент проверяет результат
   - Клиент может одобрить работу

4. **COMPLETED** (Выполнено)
   - Работа принята
   - Ожидается оплата
   - Клиент может отметить как оплачено

5. **PAID** (Оплачено)
   - Работа оплачена
   - Задание завершено
   - Отображается дата оплаты

**Кто видит:** Специалисты (только для заданий со статусом "OPEN", если специалист ещё не подавал заявку)

**Отображаемые элементы:**
- Заголовок секции: "Подать заявку на это задание"
- Форма заявки
- Кнопка отправки

**Поля формы для дизайна:**

1. **Технический подход** (обязательное)
   - Тип: Текстовая область
   - Строк: 6
   - Ограничения: 100-2000 символов
   - Плейсхолдер: "Опишите ваш подход к решению задачи..."

2. **Уточняющие вопросы** (обязательное)
   - Тип: Текстовая область
   - Строк: 4
   - Ограничения: 50-1000 символов
   - Плейсхолдер: "Какие вопросы у вас есть по требованиям?"

3. **Оценка трудозатрат** (необязательное)
   - Тип: Текстовая область
   - Строк: 2
   - Ограничения: Максимум 200 символов
   - Плейсхолдер: "Например: 2-3 недели, 40 часов"

**Доступные кнопки:**
- "Подать заявку" (основная кнопка)
  - Состояния: обычное, загрузка ("Отправка...")
  - При успехе: заявка создаётся со статусом "Pending"

**Сообщения об ошибках:**
- "Технический подход обязателен"
- "Уточняющие вопросы обязательны"
- "Технический подход должен содержать минимум 100 символов. Пожалуйста, опишите вашу методологию подробнее"
- "Уточняющие вопросы должны содержать минимум 50 символов. Что вам нужно узнать о требованиях?"
- "Технический подход слишком длинный. Максимум 2000 символов"
- "Уточняющие вопросы слишком длинные. Максимум 1000 символов"
- "Оценка трудозатрат слишком длинная. Максимум 200 символов"
- "Слишком много заявок. Попробуйте через X минут"
- "Вы уже подали заявку на это задание"

**Условия отображения формы:**
- Пользователь — специалист
- Задание не является примером
- Специалист ещё не подавал заявку на это задание
- Статус задания — "OPEN"

     - "Клиент"
     - "Специалист"

## Общие компоненты

### Компонент обмена сообщениями

**Назначение:** Обмен сообщениями между клиентом и назначенным специалистом

**Где отображается:** На странице задания (`/dashboard/gigs/[id]`)

**Кто видит:** Владелец задания (клиент) или назначенный специалист

**Условия доступа:**
- Специалист должен быть назначен на задание
- Пользователь должен быть либо владельцем задания, либо назначенным специалистом

**Если специалист не назначен:**
Отображается информационное сообщение: "Обмен сообщениями станет доступен после назначения специалиста на это задание"

---

**Отображаемые элементы:**

**Секция сообщений:**
- Заголовок: "Сообщения"
- Список сообщений (от старых к новым)
- Форма отправки нового сообщения

**Каждое сообщение показывает:**
- Имя отправителя (отображаемое имя, название компании или email)
- Содержание сообщения
- Дату и время отправки
- Визуальное выделение для сообщений текущего пользователя

**Форма отправки сообщения:**

1. **Текст сообщения** (обязательное)
   - Тип: Текстовая область
   - Строк: 3
   - Ограничения: Максимум 2000 символов
   - Плейсхолдер: "Напишите сообщение..."

**Доступные кнопки:**
- "Отправить" (основная кнопка)
  - Состояния: обычное, загрузка ("Отправка...")
  - При успехе: сообщение добавляется в список

**Сообщения об ошибках:**
- "Сообщение не может быть пустым"
- "Сообщение слишком длинное. Максимум 2000 символов"
- "Слишком много сообщений. Попробуйте через X минут"
- "Обмен сообщениями недоступен для закрытых заданий"

**Ограничения:**
- Обмен сообщениями недоступен, если задание закрыто администратором
- Лимит: 30 сообщений в час на пользователя
