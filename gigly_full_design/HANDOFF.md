# GIGLY — хэндофф в разработку

Тех-заметки для агента-разработчика. Читать до правок кода.

## Что это
Прокликиваемый дизайн-прототип, не продакшн-фронт. Цель хэндоффа — перенести визуал и поведение в реальное приложение с бэкендом. Данные захардкожены (см. `DATA-MODEL.md`) и заменяются выборками из БД.

## Архитектура файла
- Всё приложение — один Design Component `Gigly App.dc.html`: шаблон (`<x-dc>…`) + класс логики `Component extends DCLogic` (React-класс без `render()`; `renderVals()` отдаёт значения в шаблон).
- Данные-моки — поля-константы класса (`MARKET`, `GIGS`, `APPLICATIONS`, `CONVERSATIONS`, `DISPUTES`, `ADMIN_USERS`, `STATUS`, `CAT`, `FILTERS`, `NAV*`).
- Состояние — `this.state` (route, role, openGig, gigStage, фильтры, модалки, theme…).
- Навигация — смена `state.route`; хук `window.__giglyGo(...)` для дип-линков/проверки.

## Стайлинг — ВАЖНО
- **Все стили инлайновые** (конвенция DC). Глобального CSS-фреймворка нет.
- `styles.css` держит: web-шрифты, `@import` токенов и **тематический слой** — переменные в `:root` (тёмная) и `html[data-theme="light"]` (светлая).
- Цветовые литералы в `Gigly App.dc.html` и `Gig Card.dc.html` переведены в переменные: `--surface-app/card/sunken/secondary/sidebar/deep/them`, `--hairline-05..12`, `--text-1..5`, `--border-strong`, `--bubble-me`, `--nav-active-fg`, `--switch-active-fg`, `--accent-ink`, `--card-shadow*`.
- **Тёмные значения переменных = исходным литералам** → тёмная тема визуально не менялась при вводе светлой.

## Темы
- Переключатель: Настройки → Внешний вид. `applyTheme(label)` ставит `document.documentElement.setAttribute('data-theme', 'light'|'dark')`, пишет `localStorage['gigly-theme']`; `componentDidMount` читает при загрузке.
- Принцип светлой темы: глубина строится **тенью + слоями серого**, не свечением (фон #f4f5f7, белые карточки, утопленные поля #eceef1, тёмные хэйрлайны). Обоснование — `ТЗ — Светлая тема.md`.
- Синий акцент `#0088ff` и пиксельный Handjet — неизменны в обеих темах.

## Компоненты из Figma (бандл)
- `design-system/Components.bundle.js` — 62 компонента на `window.*`, грузится через `<x-import component-from-global-scope="Имя">`. Каталог — `Components.d.ts` (имена выведены из слоёв Figma, читать перед использованием). **Это рантайм прототипа.**

## Исходники компонентов для прямого переноса
- **`design-system/source/`** — каждый примитив отдельным читаемым файлом `<Имя>.jsx` + `<Имя>.d.ts` (≈58 компонентов: Button, InputField, Select, Tag, Category, Status, Gig, SideBar, HEADER, ProfileFrame, Bio, Message, Notification, Session, Filter, Switcher, CheckField, Counter, Dropdown, Menu и т.д.). Это **исходники для разработки** — реальный JSX с вариантами, пропами и стилями на токенах (`var(--spacing-md)` и пр.), а не минифицированный бандл. Брать их как источник истины по примитивам при переносе.
- `design-system/source/fig-tokens.css` + `fig-typography.css` — самодостаточный набор токенов этого слоя (unitless float → `calc(var(--x) * 1px)` на месте использования).
- **Шрифты в исходниках** названы по Figma (`NKDuy Mono`, `Vremena Grotesk`, `SF Compact`) — это РЕАЛЬНЫЕ имена начертаний для `@font-face`. В прототипе они подменены на бесплатные (см. ниже); при переносе либо подключить лицензионные оригиналы, либо повторить подмену.
- **Ограничение:** бандл-компоненты пре-транспилированы с ЗАШИТЫМИ цветами — переменные темы на них не действуют. Лечится точечными override-ами в `styles.css` (пример: `html[data-theme="light"] aside .sc-host-x span { color:… !important }` для текста профиля).
- При **рематериализации** бандла из Figma заново применить подмену шрифтов: `NKDuy Mono`→`Handjet`, `Vremena Grotesk`→`Manrope` (имена зашиты в инлайн-стили компонентов).

## Иконки
- Иконки навигации и профиля — в `design-system/extra-icons.js` (единый тонкий контур, `stroke:currentColor`, грузится в `<helmet>`). Сделано потому, что часть глифов бандл перестал экспортировать, а оставшиеся рендерились неоднородно (выбивались яркостью). Цвет иконок задаётся через `color` обёртки → следует теме.
- `icon-data.js` / `Icon.jsx` — полный набор Bootstrap Icons как данные (для прочих нужд).

## Что мок, что реальное (для интеграции)
- **Мок:** все списки/карточки, рейтинги, аватары (плейсхолдеры-кружки с инициалом), даты, суммы. Платежей нет — статус `Оплачен` логический. Проверка ИНН/КПП, email, портфолио — пострелиз.
- **Реально работает (UI-логика):** жизненный цикл гига по правам, фильтры/сортировка/поиск, табы, отклик→назначение, споры→решение, переключение/отправка в чатах, темы, настройки, все модалки/тосты/пустые/загрузочные состояния.

## Развёртка
`Gigly Развёртка.dc.html` — все экраны как кадры (клик → живой экран через `__giglyGo`). Монтаж кадров — ступенчатый по таймеру (`componentDidMount`), т.к. IntersectionObserver в этом хосте не отдаёт колбэки. При добавлении новых кадров — дописать их ключи в массив `keys` шага монтажа.

## Известные ограничения / долг
- Один большой файл-DC — при переносе разбить на компоненты по роутам.
- Инлайн-стили — при индустриализации вынести в систему (CSS-модули/Tailwind с маппингом на токены `fig-tokens.css`).
- Светлая тема: радиалы/glass у бандл-компонентов — проверять точечно при появлении новых экранов.
- Desktop-only (по ТЗ). Адаптив/мобайл и авто-тема по `prefers-color-scheme` — отдельные задачи.

## Точка входа для переноса
1. Прочитать `DATA-MODEL.md` → завести сущности/enum-ы и схему БД.
2. `ROUTES.md` → роутер и состояния экранов по ролям.
3. Перенести экраны из `Gigly App.dc.html`, заменив моки на данные API; токены/темы взять из `styles.css` + `fig-tokens.css`.
4. Контракт API вывести из действий в `ROUTES.md` (список/деталь гига, отклик, смена статуса, оплата, спор, чат, нотификации).
