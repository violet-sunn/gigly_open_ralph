# e2e-cross-cutting

## Why

Reconciliation change #15 of the E2E reconciliation plan (`openspec/planning/e2e-reconciliation.md`). The cross-screen E2E specs assert behaviours of the deleted kit (a hamburger nav, a `[role="dialog"]` confirm modal, an old theme toggle, English loading labels, English skip-link text). They span the whole app rather than one screen, so they were deferred to this single reconciliation change. Each is reconciled to the rebuilt `AppShellDesign` shell + the rebuilt screens, over the **unchanged** data layer/actions.

Investigation of the rebuilt code established each spec's fate:

- **`confirmation-dialogs.spec.ts` → DELETE.** The kit `ConfirmDialog` / `useConfirmDialog` (`app/components/ui/ConfirmDialog.tsx`, `app/hooks/useConfirmDialog.ts`) are now **orphaned — nothing in `app/` imports them.** The rebuilt screens submit Reject/Withdraw **directly with no modal** (`GigDetail.tsx` «Отозвать заявку» is a plain inline action; `ApplicationsDesign.tsx` «Принять»/«Отклонить» are plain `<form>` submits). The spec asserts a `[role="dialog"]` + `#dialog-title` «Reject Application»/«Withdraw Application» confirm flow that the reground **removed by design** (like the deleted back-button/breadcrumb/shell-cutover specs). It also calls `createTestSession(page, id, email, role)` — a 4-arg signature that doesn't match the real one-arg `createTestSession(user)` helper (it was already broken). The direct Reject/Withdraw behaviour is already covered by `e2e-applications` + `e2e-gig-detail`. **User-confirmed: DELETE.**
- **`mobile-responsive.spec.ts` → DELETE.** Every test targets the deleted kit's responsive layouts: a `button[aria-label="Toggle menu"]` hamburger, `nav div.hidden.md:flex`, `div.md:hidden.space-y-4` admin table-to-card, English nav («Dashboard»/«Browse Gigs»/«Profile»/«Sign Out»), and real-form login with non-seeded users. The design is **desktop-first (1512px prototype)** and `AppShellDesign` is desktop-only — none of those responsive components exist. **User-confirmed: DELETE** (out of scope; the responsive layouts it asserts don't exist).
- **`theme-switch.spec.ts` → REWRITE.** The current spec drives a Radix-style Select (`getByRole('button', { name: 'Тема оформления' })` → `getByRole('option', { name: 'Светлая' })`) under a «Внешний вид» *heading* — neither exists in the rebuilt `SettingsDesign`, which renders an uppercase `ВНЕШНИЙ ВИД` section label + a **`Segmented` control** on the «Тема» row («Тёмная» / «Светлая»). The shell also exposes the header **«Вид»** theme button (`aria-label="Переключить тему"`). Rewrite to: (a) the settings `Segmented` «Тема» path and (b) the header «Вид» button path; both flip the root `data-theme`, persist `localStorage['gigly-theme']`, and survive a reload (no flash). `lib/theme` is unchanged.
- **`keyboard-navigation.spec.ts` → REWRITE.** Repoint to the rebuilt shell: the skip link text is **«Перейти к основному содержимому»** (was «Skip to main content»), still the first focusable element, still activating focus to `#main-content` (`tabIndex={-1}`); the header search is `placeholder="Поиск чего угодно..."` (was `input#search`); the nav is `aria-label="Навигация"`. **Remove** the kit modal focus-trap scenarios that target `div[role="dialog"]` (the confirm modal is gone). Keep the auth-form (`/login`, `/register`) tab-order scenarios that still hold (auth is PASS-AS-IS).
- **`loading-states.spec.ts` → REWRITE.** The submit-button loading labels are English («Saving profile...», «Posting gig...», «Submitting application...», «Registering...») and the register flow uses English role buttons («Specialist»/«Client»). Reconcile to the rebuilt forms' actual disabled/pending states + Russian labels, seeding via `setE2ESession` rather than the slow real-register flow where possible.
- **`accessibility-audit.spec.ts` → RE-VERIFY (light).** Re-run axe (WCAG 2 A/AA) on the rebuilt authenticated screens (`/dashboard`, `/gigs`) plus the public `/`, `/login`, `/register`. Seed + `setE2ESession` instead of the brittle register flow. If the rebuild surfaces **genuine** axe violations, that is a real a11y regression — apply the **minimal** aria/label fix in the design component (allowed narrow exception) or, if larger, record it and descope that route with a noted rationale for a follow-up.
- **`theme-coverage.spec.ts` → PASS-AS-IS (re-verify).** It already drives `localStorage['gigly-theme']` + asserts `data-theme` and the body bg per theme across `/login`,`/register`,`/auth`,`/dashboard`,`/gigs`,`/profile`,`/settings`. Confirm it still passes against the rebuilt screens (the tokens-driven `data-theme` still applies); only touch it if a rebuilt route fails to theme.

## What Changes

- **DELETE** `__tests__/e2e/confirmation-dialogs.spec.ts` (kit confirm modal removed by design; direct actions covered by `e2e-applications`/`e2e-gig-detail`).
- **DELETE** `__tests__/e2e/mobile-responsive.spec.ts` (desktop-first design; the asserted responsive layouts don't exist).
- **REWRITE** `__tests__/e2e/theme-switch.spec.ts` to the settings `Segmented` «Тема» control + the header «Вид» button (`data-theme` flip + `gigly-theme` persistence + no-flash reload).
- **REWRITE** `__tests__/e2e/keyboard-navigation.spec.ts` to the rebuilt shell (skip link «Перейти к основному содержимому» → `#main-content`, header search by placeholder, nav `aria-label="Навигация"`); remove the kit modal focus-trap scenarios; keep the still-valid auth tab-order scenarios.
- **REWRITE** `__tests__/e2e/loading-states.spec.ts` to the rebuilt forms' real pending states + Russian labels.
- **RE-VERIFY / light-fix** `__tests__/e2e/accessibility-audit.spec.ts` (axe on the rebuilt screens; minimal a11y fix only if a genuine violation surfaces).
- **RE-VERIFY** `__tests__/e2e/theme-coverage.spec.ts` (PASS-AS-IS — confirm green, no edits unless a route fails to theme).
- Reuse the existing harness (`setE2ESession` + direct Prisma seeding into `file:./test.db`; `DISABLE_RATE_LIMIT=true`). **No `app/`/`lib/` behaviour changes** (the only permitted exception is a minimal, genuine a11y aria/label fix surfaced by axe — flagged to the user before applying).

## Impact

- **Affected:** `__tests__/e2e/{theme-switch,keyboard-navigation,loading-states,accessibility-audit}.spec.ts` (rewritten/re-verified), `__tests__/e2e/{confirmation-dialogs,mobile-responsive}.spec.ts` (deleted), `__tests__/e2e/theme-coverage.spec.ts` (re-verified, expected no-op).
- **Not touched:** `app/`/`lib/` behaviour (the shell, screens, `lib/theme`, the moderation/dispute/gig actions); the unit/integration suite (951/951 — must stay green). The orphaned `ConfirmDialog`/`useConfirmDialog` files are left in place (removing dead code is out of this change's scope).
- **Plan:** advances `openspec/planning/e2e-reconciliation.md` from 14/16 → 15/16.
